# HarnessHub 治理模型

状态：Confirmed v0.1

初始 Founder：YeraldoSmith

## 1. 治理结构

```text
Founder — YeraldoSmith
 |
 ├── Administrator
 |
 ├── Moderator
 |
 └── Reviewer
```

结构表示任命与最高责任关系，不表示所有日常操作都必须由 Founder 执行。权限遵循最小授权、职责分离和全程审计。

## 2. Founder

唯一身份：**YeraldoSmith**

权限：

- 任命和撤销 Administrator；
- 修改核心规则与治理模型；
- 项目最高维护权限；
- 决定正式产品方向和官方资产授权；
- 在重大安全事件中采取临时紧急措施。

约束：

- Founder 标识不得复制或通过普通后台转移；
- 核心规则修改需要记录理由、日期和影响；
- 审核与处罚仍应引用公开规则并保留申诉路径；
- 不得通过治理决定改变第三方内容原有版权归属。

未来若需要 Founder 继任，必须通过单独、公开、可验证的治理修订完成；当前版本不提供转移机制。

## 3. Administrator

权限：

- 用户管理；
- 插件管理；
- 申诉处理；
- 任命或撤销 Moderator、Reviewer（仅在 Founder 授权范围内）；
- 执行已批准的官方账号管理和运营配置。

限制：

- 不可转移、复制或撤销 Founder；
- 不可修改项目核心归属；
- 不可删除或改写既有审计记录；
- 不应独自处理与本人、本人插件或直接利益相关的申诉；
- 不可绕过版本级安全门禁直接伪造审核通过状态。

## 4. Moderator

职责：

- 评论与社区内容治理；
- 社区规则执行；
- 处理垃圾信息、骚扰、冒充和普通内容举报；
- 记录措施、理由、有效期和证据摘要。

限制：

- 不管理平台角色；
- 不修改插件扫描结果；
- 不以负面评价本身作为删除理由；
- 高影响账户处罚和复杂申诉交由 Administrator。

## 5. Reviewer

职责：

- 插件审核；
- 风险复核；
- 检查来源、许可证、权限、安装脚本和扫描发现；
- 对发布、要求修改、限制或拒绝给出有依据的决定。

限制：

- 不授予 Founder 或 Administrator；
- 不修改项目核心规则；
- 不审核本人开发、直接参与或存在明显利益关系的插件；
- 不把一次审核描述为永久安全保证。

## 6. 权限矩阵

| 操作 | Founder | Administrator | Moderator | Reviewer |
|---|---:|---:|---:|---:|
| 修改核心规则 | ✓ | — | — | — |
| 任命 Administrator | ✓ | — | — | — |
| 管理普通用户 | ✓ | ✓ | 有限 | — |
| 处理社区内容 | ✓ | ✓ | ✓ | — |
| 审核插件版本 | ✓ | ✓ | — | ✓ |
| 处理普通申诉 | ✓ | ✓ | — | 建议/复核 |
| 修改 Founder 归属 | 单独治理修订 | — | — | — |
| 删除审计历史 | — | — | — | — |

“✓”仍受利益回避、二次确认和审计要求约束。

## 7. 任命与撤销

- 任命必须记录授予人、角色、范围、理由、生效时间和可选到期时间；
- Moderator 和 Reviewer 可以按具体范围授权；
- 撤销后立即停止新操作权限，但历史决定保留当时角色信息；
- 高权限账号应使用强认证并定期复核；
- 临时停权不应自动删除账号内容或历史记录。

## 8. 决策与透明度

- 核心政策使用版本号和变更记录；
- 插件与社区个案记录适用政策版本；
- 重大治理变化应在生效前公告；紧急安全变更可以立即生效，但需事后说明；
- 处罚通知说明事实、规则、措施、期限和申诉方式；
- 定期发布不含个人敏感信息的聚合透明度报告。

## 9. 紧急权限

Founder 或明确授权的 Administrator 可以在活跃安全事件中临时关闭安装入口、限制受影响版本或冻结高风险账号。紧急措施：

1. 必须写入审计日志；
2. 只持续到完成初步复核所需的时间；
3. 不允许远程、静默删除用户本机插件；
4. 应尽快通知受影响方并提供复核或申诉渠道。

## 10. Phase 2-B1 实施边界

Phase 2-B1 已实现 GitHub 登录、Founder 数据库 bootstrap、独立 RoleAssignment/BadgeGrant 和服务端 Session。尚未实现角色管理 API 或治理后台；因此没有普通客户端路径可以授予、撤销或转移 Founder。后续每个治理写操作仍需独立授权策略、recent authentication 与安全评审。
