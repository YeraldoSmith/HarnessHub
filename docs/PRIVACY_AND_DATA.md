# 隐私与数据处理说明 / Privacy and Data Handling

状态：Public Beta
更新：2026-08-21

> 这是 Beta 阶段的透明度说明，不取代适用司法辖区要求的正式隐私政策。正式公开
> 运营前应根据实际部署位置、运营主体、处理者、用户所在地和功能范围完成法律审阅。

## 本地保存的数据

Desktop 的 Runtime 准备、受管 Profile、插件状态、安装审计、Runtime 日志和外观
设置默认保存在本机应用数据目录。它们用于运行、恢复和解释本地操作，不会因为
浏览 Marketplace 自动上传到 HarnessHub。

## 可能访问的远程服务

根据用户操作和配置，HarnessHub 可能与以下服务通信：

- HarnessHub API：读取 Registry、公告、身份或同步功能；
- GitHub OAuth：仅在用户主动选择 GitHub 登录时；
- GitHub / npm：读取公开插件来源和固定版本元数据，或下载用户明确确认的固定依赖；
- Node.js 官方分发：下载受控 Runtime 所需的固定版本工具链。

网络请求的可用性与内容由相应第三方服务管理。不要在可公开访问的插件元数据、
README、issue、日志或错误截图中填写密钥与私人数据。

## GitHub 登录

GitHub 登录可选。平台以 GitHub 稳定数字用户 ID 而不是用户名、显示名或邮箱进行
身份绑定。OAuth Token 不会交给 Desktop 前端；会话由服务端管理，Desktop 使用
操作系统安全凭据存储保存不透明会话数据。相同邮箱不会自动合并账号。

## API Key 与 DSH

模型 API Key 的设置和使用由本地 DSH 工作区负责。HarnessHub 不要求、读取、
上传或存储用户的模型 API Key。用户仍应根据 DSH 与模型供应商的文档自行决定
如何管理凭据。

## 用户选择与控制

- 可不登录使用基础本地功能；
- 可停止 Runtime、卸载受管插件并清除本地应用数据；
- 登录后可在 Account 中退出登录；
- 云端同步、公告已读和未来社区功能应明确说明是否启用及其数据范围。

当前未提供一项中心化的“删除所有远程账户数据”自助入口；正式服务上线前应提供
明确的联系和数据主体权利处理渠道。
